# Asset and Localisation Manager

## Outcome and ownership
The owner requested the next authoring slice after quests: project-owned images and translated text that can be assigned to existing items, actors and quests. Core owns canonical metadata, deterministic validation, assignments and text fallback. Foundation owns bounded file intake, intent evidence and save-before-publish transactions. Qt presents drafts and previews. The existing asset-browser/native preview route remains independently owned.

## Contracts
Catalog schema 7 adds ProjectAssets, LocalisationEntries and PresentationBindings. Images are pack-owned synthetic assets/image records; text is pack-owned synthetic localisation/text. Binding identities are stable and scoped to the owning pack, target record and slot. Targets are native items/actors or same-pack authored items, actors and quests. Image slots are item icon and actor portrait; text slots are name and description (including quest summary). An explicit empty binding clears an assignment while retaining its identity and intent. Bindings cannot silently overwrite another pack's declarations.

Images use decoded PNG/JPEG bytes, a SHA-256 fingerprint, byte count, dimensions, portable workspace-relative path, provenance and user-declared source rights. Intake reads at most 8 MiB and decodes at most 4,194,304 pixels, with each dimension at most 4096. Paths are resolved through existing ancestors before directory creation; managed content stays inside the canonical workspace and outside configured game/extraction/engine roots. New immutable content-addressed files precede catalog publication. A failed catalog save leaves prior catalog/assignments intact; unreferenced new files may remain for explicit future cleanup. Existing content is never overwritten or deleted.

Text keys are exact, case-sensitive and unique within a pack. Each entry has 1-32 language variants, an explicit default language, and at most 8192 UTF-8 bytes per variant. This slice accepts lowercase language identifiers of 2-16 ASCII letters/hyphens (such as en and en-gb), not the complete BCP-47 grammar. A missing requested variant uses the declared default and reports the fallback. Preview text is plain text. Collections and aggregate text bytes are bounded. Revisions cover semantic metadata; editing a stale revision fails before publication.

Source rights are author declarations, not verified redistribution permission. All existing governance/runtime permission axes remain unchanged. Assignments describe local authoring intent and do not mutate native records or execute game operations. Manager preview explicitly resolves assignments for the active pack; available actor/item image consumers use the same service.

## Persistence and compatibility
New writes emit schema 7. Schemas 1-6 remain load-only inputs; their first save preserves and verifies the exact old bytes using the existing migration backup mechanism. Old versions carrying new collections, malformed entries, duplicate keys/identities, wrong-owner references and future versions fail closed. Catalog load validates metadata without requiring every image file to exist, allowing users to repair missing files in the Manager. Reading or assigning an image checks its actual contents and fingerprint. Workspace/pack, QuestDefinition V1, canonical interchange, runtime and installer contracts do not change. Downgrade requires restoring the pre-migration backup; the older editor cannot represent schema-7 authoring data.

## UI and proof
One registered pane provides image/text lists and drafts, language editing, immediate selected-entry previews, assignments, clear/reassign, save/revert and mod selection. Dirty drafts survive context switches; saving into a different workspace/profile/pack is disabled. File IO/decoding occurs only for explicit intake or selected-image preview, never for every row or render event. List filtering does not hash files or serialize the catalog. Live acceptance measures the established three-second maximum UI timer gap and uses synthetic owned images/text.

Required proof: focused Core/Framework tests for metadata limits, deterministic fallback/revisions, duplicate keys, ownership, dangling/cleared assignments, stale edits, image signature/dimensions/hash/path rejection, failed-save preservation, save/reopen and schema-6 backup/migration; pinned O3DE configure/build/full affected tests; static/source policy; live Editor preview and editing acceptance with visual inspection. Mesh/audio authoring, translation import/export, native intake, Unity conversion, packaging and FoA runtime execution remain later slices.
